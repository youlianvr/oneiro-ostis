> Утверждён владельцем 2026-10-12 и является главным планом проекта. Этапы S1–S9 и
> матрица приёмки §6 в `docs/MASTER-PLAN.md` остаются историей и списком доказательств,

> Состояние, проверки и следующий шаг — в `docs/PROGRESS.md`.

## 1. Стоп-критерий готовности

Проект готов, когда выполнены все пункты §5 с доказательствами и выполнено условие §0
`MASTER-PLAN.md`: человек без помощи устанавливает Oneiro, открывает окно, ведёт разговор,
видит каждый вызов инструмента и каждое подтверждение, ставит задачу по расписанию,
закрывает и открывает снова. Ни один экран не показывает JSON, ни одна панель не врёт,
ни одна незаявленная возможность не работает.

## 2. Идея владельца (не меняется)

1. Oneiro — собственный ИИ-агент, а не обёртка над чатом.
2. Опыт записан типизированными связями в граф знаний OSTIS.
3. Агент действует в изолированной среде, а не на основной системе.
4. Агент начинает работу сам: по расписанию и по внешнему событию.
5. Агент учится на собственных записях.

Демо-цепочка: письмо или вебхук → задача → сообщение вам в Telegram → черновик во вкладке
«Черновики» → ваше нажатие «отправить» → задача из GUI → офисная работа в изолированной
среде → запись в графе памяти.

## 3. Решения владельца (зафиксированы 2026-10-12)

| Что | Решение |
|---|---|
| Изолированная среда | Контейнер Docker. Это песочница процессов, а не отдельная машина: ядро общее с WSL2. В речи «изолированная среда», без слова «машина». |
| GUI-агент | Снят с плана: управление экраном, клик и ввод не делаем. В докладе — направление развития. |
| Вебхук | Контракт повторяем в Oneiro. Локальный POST на консоль, ничего наружу. HMAC-SHA256; без подписи — отказ с причиной. Секрет генерирую и кладу в `.oneiro`, в отчётах не печатаю. |
| Почта | Чтение входящих плюс отправка ответа, но каждая отправка только по вашему нажатию в черновике. |
| Черновики | Два пути сразу: сообщение вам в Telegram (личка от бота) и вкладка «Черновики» в консоли с кнопкой «отправить» и полем доработки. Без нажатия ничего не уходит. |
| Telegram | Бот пишет вам в личку, `chat_id` беру из `get_updates`. Инструмент `telegram-mcp-bot`. |
| Офис | Изолированная среда создаёт документ, таблицу и презентацию и конвертирует их в PDF. Графика не нужна. |
| Демо | Из исходников, отдельная директория, отдельный корень данных, свободный порт. Рабочие граф и настройки не трогаются. |
| Записи демо | Отдельный субъект опыта для демо, чтобы не смешивать с рабочими записями. |
| Модель | Облачный API через ваши ключи. Если в зале нет сети — запасная запись демо. |
| Файлы демо | Временная папка демо, после демо чистится. |
| Самоулучшение | Доказательство — замер с тремя повторами на задачу. Работа за параллельным агентом. |
| Стоп-точки | Останавливаюсь и спрашиваю только перед внешними действиями: отправка почты, отправка в Telegram за пределами демо, что-либо наружу из машины, публикации. Остальное авторизовано, включая коммиты. |
| Отчёты | После каждой готовой работы короткий отчёт с кодами выхода, с объяснением, без остановки ради этого. |
| Речь | Русский, 10–12 минут, от первого лица. Докладчик: Ступчик Юлиан Владиславович. Руководителя не называем. Про ИИ-ассистентов в разработке не говорим. Слайды (PPTX) — после форума. |
| План | Этот файл — главный. `MASTER-PLAN.md` получает баннер. |

## 4. Вне плана (записано, чтобы не потерять)

- Два открытых дефекта аудита: форма конфига не сообщается как ошибка; хеш манифеста зависит
  от чекаута.
- Отложенные: mypy-override, нестабильность строки настроек, DOM-drift клиента.
- Гипервизорная ВМ (Hyper-V) и отдельный дистрибутив WSL2 — путь развития.

## 7. Промт параллельному агенту (вставить как есть)

> Ты работаешь параллельно с A1 в одном репозитории `projects/ostis/oneiro-ostis`. Возьми
> пункт O8 плана `docs/READY-2026-10-12.md`: ядро самоулучшения на текущем графе. Работай
> только в новых файлах: `python/oneiro/dream/`, `tests/test_dream*.py`, `docs/O8-<дата>.md`.
> Не правь `web.py`, `pages.py`, `tools.py`, `vm/` и `docs/READY-2026-10-12.md`. Отметь себя
> сразу: `python _scripts/parity_claim.py new dream-o8`.
>
> Приёмка: повтор идёт только по записям и никогда не исполняет мир (тест подменяет шаг мира
> функцией, обязанной возбудить исключение); покрытие возвращается числом, непокрытые шаги
> усекают эпизод, судья не додумывает исход; кандидат замеряется не менее чем тремя повторами
> на задачу, разброс показывается; промоция только за шлюзом и с откатом. Числа и команды с
> кодами выхода запиши в `docs/O8-<дата>.md` и строкой в свой файл на доске парити. Коммить
> только свои файлы. Общение — через `_memory/parity/`.
