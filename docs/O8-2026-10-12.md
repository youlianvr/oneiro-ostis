| `python/oneiro/dream/gate.py` | The gate: rules frozen before the run, a verdict that names every failed check, promotion only on evidence about *that* candidate, and a rollback that is a new revision of the same release. |

## 3. The judge: what is a number here, and what is not

The graph records, for a turn: the owner's message, every call with the observation the
model was given, the decision, the state and the final reply. It does **not** record the
assembled prompt, its size, per-step token counts, the model's own tool-call IDs, the
assistant's text before a call, or the tool catalogue as it was offered. `NOT_RECORDED`
names all of it, every report carries that list, and `Episode.unrecorded` names it again
per turn, so no estimated figure can be read as a measured one.

Coverage is a comparison against the recorded policy on the same rebuilt context: the
history and facts blocks are the same object in both reconstructions, so whatever they
are cancels, and what remains is exactly what a candidate changes. It is therefore only
as good as the turn that was recorded — a caveat carried on every estimate, not buried
here.

The round trip is proven against real turns and not only against turns the suite made: **every**
turn this lane has recorded rebuilds to its stored rows byte for byte — **`rows_match` 24 of 24**,
over six sessions: the fourteen answered turns of the measurement of record, the six the first
resumption bought, and the four the fixing resumption bought once the product defect was closed
(§5). Every one of the twenty-four has its six-message prelude read back, the recorded policy
covers every step of every one of them (mean coverage **1.000**) and `windowed` covers none (mean
**0.000**). The check is read-only and its exact command is in §8.

## 4. The live leg

* **Nothing is estimated.** Each repeat is a real turn through `models.registry()`: the
  provider list the settings declare and the model a role resolves to. No model name is
  written into `measure.py`, so a measurement cannot be tied to whichever model answered
  today.
* **A knob the live turn cannot be told to read is refused by name.** The turn reads
  `chat.history_messages` (`agent.py:359`), `chat.context_chars` (same) and
  `agent.max_turns` (`agent.py:344`) from the settings; there is no switch for the facts
  block or for a tool-observation limit yet. `apply_policy` raises `MeasureError` naming
  `include_facts` rather than measuring a policy that was never in force.
* **The demo is its own subject.** Records go to the `dream` stream — never the stream
  the owner's own work is in — and settings and leases live under a root of their own,
  seeded from the owner's configuration with every secret left where it belongs. The
  fixtures are named by absolute path: a *read* is not rooted at the working folder (only
  a *write* is), so a task that depends on the process working directory is not a task.
* **A measurement cut short is completed, not repeated.** `--save` writes the payload and
  `--resume` reads it back: the runs it holds are kept exactly as they were observed, their
  verdicts are re-read from their own records (a scoring rule may have changed since, so a
  stored flag is not trusted), and only the repeats that failed are run. A payload the graph
  will not let it read stops it with a named error instead of quietly buying those runs again
  — measured 2026-10-12: the first version did the opposite and bought seven recorded runs a
  second time, three of which then died (§5, §6).
* **Nothing is left running.** The leg opens the product's own graph worker, measures and
  closes it; no server, no port, nothing to leak.

## 6. What went wrong on the way, and was fixed

* **A relative path in a task read the wrong directory.** The first live attempt had
  `read_file` resolve `NOTES.md` against the process working directory (the project
  checkout) instead of the demo workspace, because `tools.readable` resolves relative
  paths against the cwd — only writes are rooted at `tools.workspace`. Every repeat was
  recorded as a failure to find a file that was in fact written. Fixed by naming fixtures
  absolutely (`Task.request_for`), which is how the shipped tasks read now; guarded by
  `test_no_task_depends_on_the_process_working_directory` and
  `test_the_fixture_is_reachable_through_the_real_tool`. The records of that first attempt
  stay in the `dream` stream under session `688fef6b` — evidence, not something to tidy
  away.
* **`from oneiro.dream import measure` binds the function, not the module.** The package
  rebinds `measure` and `propose` to the functions of those names, so `cli.py`'s module
  aliases were functions and `measure_module.owner_for` would have raised at the first
  CLI call. Found by running the CLI as a process; fixed by importing from the submodule
  paths, and the footgun is now written down where it bites.
* **The round-trip proof was false on real turns.** `verify_reconstruction` counted the
  history block's own assistant messages as this turn's calls, so `rows_match` was `False` on
  all fourteen turns of both live measurements — on the very turns the acceptance clause
  "exact replay of records" exists to prove. Fixed by comparing only the messages after the
  request, and guarded by `test_a_turn_in_a_conversation_with_a_prelude_still_verifies`,
  which records a turn in a conversation that already has exchanges of its own. After the
  fix every turn this lane has recorded verifies: **`rows_match` 24 of 24** over six
  sessions, mean coverage 1.000 for the recorded policy and 0.000 for `windowed` (§5).
  (The first re-check was blocked for a while by
  the graph aborting fresh connections — `server_unreachable: resolve_keynodes failed` —
  which is the same condition that made `python -m oneiro.dream record` fail earlier; it
  cleared and the check then ran.)
* **The answers were scored by one string, and it was wrong** — "keep **things** small" is a
  correct answer that a single expected `"keep it small"` counts as a failure. `Task.answers`
  is a tuple now, and §5 records that the first score was mine being wrong.
* **The first resumption bought seven measured runs a second time.** `record_verdict` treated a
  read the graph would not serve as "there is no run here", so those runs were dropped and their
  repeats run again: **seven** recorded runs bought a second time (six single-call turns and one
  repeat of the third task), three of which then died with the graph aborting the lane — eleven
  turns bought in all where four were owed. That is the opposite of what a resume is for, and it is
  how it was found. Fixed: the read is retried (`RECORD_ATTEMPTS`,
  because the graph aborts the first calls of a freshly opened lane) and then refused by name —
  `the record of <turn> cannot be read, so this measurement cannot be resumed` — while a record
  that is genuinely *not there* still means "run that repeat". The two cases are guarded
  separately (`test_a_resume_stops_when_the_graph_will_not_serve_its_own_records`,
  `test_a_reused_run_whose_record_is_gone_is_measured_again`), and the second live resumption is
  the fixed behaviour in action: it refused before spending anything (§5).
* **The product defect this leg found, and then fixed on an approved plan.** Two tool calls in one
  assistant message shared an action ID — the step index advanced per message instead of per call —
  so the store refused the second call (`operation_collision`) and the turn died before it answered.
  It cost four of the eighteen runs in the measurement of record and seven of the eleven attempts
  this lane had then made at the multi-call task (§5). Fixed by numbering a step per call; the four
  missing repeats were then bought on the payload already held, and one of them is the proof live:
  four steps from three model calls, answered. The change is in `agent.py`, which is outside the
  new-files-only mandate this package began under; the owner approved the plan before the work, both
  `agent.py` and `tests/test_agent_loop.py` were clean when edited, and the parity board records the
  widening. Guarded by `test_two_calls_in_one_message_are_two_steps_and_both_run`.
* **`measure(owner=None)` was a type error waiting to happen.** `mypy` caught the
  optional subject; the subject is now required.
